# 维护与验证记录

## 已查明的原因

1. 页面上的 `/F9` 与内嵌 Form 的 `/F9` 可以指向不同字体，字符编码长度也可能分别是一字节、两字节。原代码以页面映射覆盖局部映射，导致数学字形无法正确渲染。
2. 全文字体裁剪会改动原字体的字距及字形数据。原文像素比较发现变化，修复后只裁剪新嵌入字体，并保留 glyph ID。
3. `mm²` 单独保存在很小的 Form 内。它随译文移动后，仍受原 Form BBox 裁剪；现在与邻近数值一起排版，并在页面坐标中绘制，保持源字体作用域。
4. Source Han 字体的普通连字符与不换行连字符共享 glyph。默认 ToUnicode 可能选择后者，导致复制文字与完整性检查不一致。用实际输出文字补充映射，且保留其他已有映射。
5. 保存后的 cmap 规范化曾只保留“有轮廓”的 glyph，删除空格映射，造成 U+0001/U+0003。现在保留全部已有 cmap 条目。
6. DeepSeek 原适配器只把 thinking 设置传给特定旧命名模型，新别名忽略关闭思考的设置。当前修复覆盖 `deepseek-flash`。

## 修改原则

- 阅读 `patches/review` 中对应 diff；在修改源码后同步更新 patched 文件与 SHA256 清单。
- `original` 必须来自 `release.lock.json` 对应的官方原始 ZIP，不用一台机器上已经改动过的文件作基线。
- 版本、原文件或 payload 校验不通过时，部署脚本拒绝覆盖，不提供绕过校验的 force 参数。
- 保持原文已有字体与资源作用域；渲染异常时停止输出，不能靠删掉公式或字符使校验通过。
- 只使用原始论文通过软件重新翻译来证明修复有效，不能把人工修补过的 PDF 当作软件回归结果。
- 保留 API 配置在本机用户目录，不把真实配置复制进工程或上传 GitHub。
